| ファイル | 中身 |
|---|---|
| `sample-data.sql` | 見本のデータを作る SQL。**はじめに、今あるデータをすべて消す** |
| `run-on-aws.sh` | 本番のデータベースに、`sample-data.sql` を流す（AWS の中で、1回だけ動く小さな箱から流す） |

## 入っているデータ

- **利用者 30人：** オーナー 5人（確認用のアカウントを含む）、運営スタッフ 10人、ふつうのメンバー 15人。メールアドレスはすべて `@example.com`（例として使うためのアドレスで、メールは届かない）
- **コミュニティ 12件**（1件はアーカイブ済み）、**イベント 24件**（開催前と終了済み）、**申込み 126件**、**お知らせ 10件**
- 日時は、SQL を流した時刻から作る（開催前のイベントは、流した日から数日〜25日後）

**確認用のアカウント**（`demo@example.com`）で、一通りの機能を確かめられる：

| 立場 | 確かめられること |
|---|---|
| オーナー | 自分のコミュニティ 3件（＋アーカイブ済み 1件）。メンバー管理（運営スタッフ・メンバー）、承認待ちの参加の申請（3件）、イベントの作成・編集・削除、申込者一覧（承認待ち・申込み済み・キャンセル待ち・却下）、締め切り後のイベント、終了したイベント |
| 利用者 | ほかのオーナーのコミュニティ 5件のメンバー。開催前のイベント 5件に申込み（申込み済み・承認待ち・キャンセル待ち・却下）。参加の申請中のコミュニティ 1件。お知らせ（未読 3件） |

ほかの利用者のパスワードは、ランダムに作り、どこにも残さない（ログインできるのは、確認用のアカウントだけ）。

## 入れ方

### 手元で試す

```bash
docker cp infra/sample-data/sample-data.sql （データベースの箱）:/tmp/sample-data.sql
docker exec （データベースの箱） psql -q -U campfires -d campfires -v demo_password=（パスワード） -f /tmp/sample-data.sql
```

### 本番に入れる（本番のデータは、すべて消える）

```bash
DEMO_PASSWORD='（確認用のアカウントのパスワード）' bash infra/sample-data/run-on-aws.sh
```

- 本番のデータベースは VPC の中にあるので、AWS の中で 1回だけ動く小さな箱（ECS のタスク。PostgreSQL の公式のイメージ）を起動して、そこから流す
- データベースの利用者とパスワードは、Secrets Manager から ECS が箱に渡す。相手が本物の RDS かを、証明書で確かめる
- SQL は1つのまとまり（トランザクション）で流すので、途中で失敗したときは、何も変わらない
- 今ログインしている人は、全員ログアウトされる
