# 要件定義書

## 1. 概要

Campfires は、勉強会やコミュニティの運営者のためのイベント申込み管理アプリです。

1つのアプリの中に、独立したコミュニティがいくつも存在します。各コミュニティには1人のオーナーがいて、そこにメンバーが集まり、イベントに申し込みます。

名前は「広い野原のあちこちで焚き火（コミュニティ）が灯り、それぞれに人が集まってくる」様子から付けています。

関連する文書：

- [非機能要件](non-functional-requirements.md)：速さ、安全さ、止まりにくさなど、品質についての要件
- [画面一覧](screens.md)：MVP で作る画面と URL
- [法的な論点のメモ](legal-notes.md)：関係する法律と、対応する・しないの判断

## 2. 用語

| 用語 | 意味 |
|---|---|
| ユーザー | アカウント登録をした人 |
| 管理者 | このアプリを運営する人。コミュニティのオーナーや運営スタッフとは別 |
| 本名 | ユーザーの本当の名前。本人と管理者だけが見られる |
| ニックネーム | ほかのユーザーに表示される名前。オーナーや運営スタッフにも、ニックネームだけが見える |
| コミュニティ | ユーザーが作るグループ。イベントはコミュニティの中で開かれる |
| オーナー | コミュニティを作った人。1つのコミュニティに1人 |
| 運営スタッフ | オーナーに任命されたメンバー。運営を手伝う |
| メンバー | コミュニティへの参加が承認された人 |
| イベント | コミュニティで開かれる勉強会など。定員がある |
| 申込み | メンバーがイベントに参加を申し込むこと |
| キャンセル待ち | 満席のイベントに申し込んだとき、空きを待つ状態 |
| コミュニティ退会 | メンバーが、1つのコミュニティから抜けること。アカウントは残る |
| アカウント削除 | ユーザーが、アプリそのものをやめること。個人情報を消す |

## 3. 利用者と権限

コミュニティの中での立場（ロール）は、オーナー、運営スタッフ、メンバーの3種類です。同じユーザーでも、コミュニティごとに立場が異なります。

| できること | オーナー | 運営スタッフ | メンバー | 参加していないユーザー |
|---|:-:|:-:|:-:|:-:|
| コミュニティの詳細を見る | ○ | ○ | ○ | ○ |
| コミュニティの情報を編集する | ○ | × | × | × |
| コミュニティをアーカイブする・元に戻す | ○ | × | × | × |
| 参加を申請する | - | - | - | ○ |
| 参加申請を承認・却下する | ○ | ○ | × | × |
| 運営スタッフを任命・解除する | ○ | × | × | × |
| メンバーを除名する | ○ | × | × | × |
| イベントを作成・編集・削除する | ○ | ○ | × | × |
| イベントの一覧・詳細を見る | ○ | ○ | ○ | ○ |
| イベントに申し込む・キャンセルする | ○ | ○ | ○ | △（※） |
| イベントの申込者一覧を見る | ○ | ○ | × | × |
| イベントの参加を承認・却下する | ○ | ○ | × | × |
| コミュニティを退会する | × | ○ | ○ | - |

※ 参加していないユーザーは、イベントが「メンバー以外」の参加を受け付けているときだけ申し込める（5.12）。

コミュニティに関係なく、ログインしているユーザーは誰でも、自分のアカウントを削除できます。

## 5. 業務ルール

### 5.1 コミュニティ

- オーナーは退会できない。オーナーがやめるときは、コミュニティをアーカイブする（5.9）
- 参加申請の状態は「申請中」「承認済み」「却下」の3つ
- 却下された人は、もう一度申請できる

### 5.2 イベントと申込み

- 申し込めるのは、そのコミュニティのメンバー（オーナーと運営スタッフを含む）。イベントが受け付けていれば、メンバー以外も申し込める（5.12）
- 1人が同じイベントに申し込めるのは1回だけ
- 申込み数が定員に達したら、それ以上は申し込めない（MVP の後半からは、キャンセル待ちになる）
- 定員を、今の申込み数より少なくすることはできない

#### イベントの場所

- 場所の入力欄の近くに、「自宅の住所など、個人の住所は入力しないでください。イベントの情報は、ログインしていない人も含めて誰でも見られます」という注意書きを表示する
- イベントの作成と編集の、どちらの画面でも表示する

#### 申込み締め切り日時

- イベントを作るとき、オーナーまたは運営スタッフが「申込み締め切り日時」を必ず入力する。開始日時より前でなければならない
- 締め切り日時を過ぎたイベントには、新しく申し込めない（キャンセル待ちにも登録できない）
- 締め切り日時は、キャンセルの期限も兼ねる。締め切り後は原則としてキャンセルできないという扱いにする
- ただし、締め切り後もキャンセルの操作自体はできる。その場合は「申込みの締め切りを過ぎています。原則としてキャンセルはできません。本当にキャンセルしますか？」という確認を出す。守るかどうかは参加者に任せる
- 締め切り後にキャンセルが出た場合は、キャンセル待ちの繰り上げ（5.3）を行わない。空いた枠はそのまま空きとする
- 締め切り後にキャンセルが出た場合は、そのイベントのコミュニティのオーナーと運営スタッフに、アプリ内のお知らせで通知する（F-20、5.10）

#### イベントの削除

- 開催前のイベントは、オーナーと運営スタッフが削除できる。終了したイベントは、参加の記録として残すため削除できない
- 削除すると、申込み（承認待ち、キャンセル待ちを含む）も一緒に削除する
- 申し込んでいた人には、アプリ内のお知らせで、イベントが削除されたことを通知する（F-20、5.10）

### 5.3 キャンセル待ち（MVP の後半）

- キャンセル待ちは、申し込んだ順に並ぶ（手動で承認するイベントでは、承認された順。5.12）
- 締め切り日時より前に申込みがキャンセルされたら、キャンセル待ちの先頭の人が申込み済みになる
- 締め切り日時を過ぎたら繰り上げは行わない。そのときキャンセル待ちだった人は、キャンセル待ちのまま確定する

### 5.4 コミュニティ退会

- コミュニティを退会すると、そのコミュニティの開催前のイベントへの申込み（キャンセル待ちを含む）は、すべてキャンセルされる
- 終了したイベントの申込みの記録は残す
- 退会した人は、もう一度参加を申請できる

### 5.4.1 メンバーの除名

- 除名できるのはオーナーだけ。メンバーだけでなく、運営スタッフも除名の対象にできる
- 除名された人の申込みは、5.4 のコミュニティ退会と同じく、開催前のものがすべて自動でキャンセルされる
- 除名する前に、必ず確認の画面を出す。申込みがあるかどうかに関係なく、「除名すると、このメンバーの開催前のイベントへの申込み（キャンセル待ちを含む）は自動的にキャンセルされます」と表示する
- 除名された人は、もう一度参加を申請できる。承認するかどうかは、オーナーと運営スタッフが判断する

### 5.5 アカウント削除

- オーナーをしているコミュニティがある場合は、次の2つを両方満たすまで、アカウントを削除できない（オーナーを引き継ぐ機能は MVP にないため）
  - オーナーをしているコミュニティが、すべてアーカイブ済みであること
  - それらのコミュニティに、開催前のイベントが残っていないこと（管理する人がいないイベントが生まれないようにするため）
- オーナーがアカウントを削除したあとも、アーカイブ済みのコミュニティは残る。オーナーは「退会したユーザー」と表示され、元に戻すことはできなくなる
- アカウントを削除すると、参加しているすべてのコミュニティから退会する。開催前のイベントへの申込みは、5.4 と同じくすべてキャンセルされる
- 本名、ニックネーム、メールアドレスは消す。過去の申込みの記録は、行ごとは消さず、申込者を「退会したユーザー」と表示する。記録の数が急に変わって、運営側が混乱しないようにするため
- パスワードの情報も消し、二度とログインできないようにする
- 削除したあと、同じメールアドレスで新しくアカウントを登録できる
- 削除する前に確認の画面を出し、パスワードをもう一度入力してもらう。本人の操作であることを確かめるため

### 5.6 本名とニックネームの扱い

- アカウント登録のとき、本名とニックネームを別々に入力する。どちらも必須
- ほかのユーザーに表示するのは、ニックネームだけ。コミュニティのオーナーと運営スタッフにも、本名は表示しない
- 本名を見られるのは、本人（アカウント設定の画面）と管理者だけ
- 本名は、本人確認、問い合わせへの対応、不正な利用があったときの対応のために使う
- メールアドレスも、本名と同じく、本人と管理者だけが見られる
- ニックネームは、アカウント設定の画面でいつでも変えられる。変えると、過去の申込みの記録を含めて、すべての画面で新しいニックネームが表示される
- 本名とニックネームの扱いは、プライバシーポリシーに書く

### 5.7 プライバシーポリシー・利用規約

- アカウント登録の画面に、両方へのリンクと「同意する」のチェックを置く。チェックしないと登録できない
- 両方のページは、ログインしていなくても見られる
- 内容を変えたときは、変えた日と内容をページに書く
- 利用規約に、16歳未満は利用できないことを書く
- 利用規約に、パスワードを忘れた場合と、本名やメールアドレスを変えたい場合は、問い合わせで対応することを書く

### 5.8 イベント一覧と検索

#### 表示するイベント

- 表示するのは、開催前のイベントだけ。終了したイベントは、一覧にも検索結果にも表示しない（終了したイベントは、コミュニティ詳細から見る）
- 誰でも（ログインしていなくても）見られる
- 各イベントには、どのコミュニティのイベントかも表示する

#### 何も検索していないとき

- **ログインしているとき**：自分が申し込んだ開催前のイベント（キャンセル待ちを含む）を、開始日時の近い順に、**全件**表示する。各イベントに「申込み済み」「キャンセル待ち」を表示する。終了したイベントと、キャンセルした申込みは表示しない
- **ログインしていないとき**：すべての開催前のイベントを、作成日時の新しい順に表示する（表示のしかたは、下の「件数と読み込み」のとおり）

#### 検索したとき

- ログインしているかどうかに関係なく、すべての開催前のイベントから探す（まだ参加していないコミュニティのイベントも見つけられるようにするため）

#### 検索のしかた

- 検索の対象は、イベントのタイトルと説明
- 入力した単語が含まれていればヒットする（部分一致）
- 単語は、空白（半角・全角のどちらでもよい）で区切って、いくつか入力できる
- 英字の大文字と小文字は区別しない（`java` でも `Java` でもヒットする）
- 全角と半角の英数字は区別する（`Ｊａｖａ` と `Java` は別の単語として扱う）

#### 複数の単語を入力したときの並び順

- 1つでも単語が含まれていればヒットする
- 当てはまった単語の数が多い順に並べる。すべての単語を含むイベントが一番上に来る
- 当てはまった単語の数が同じなら、作成日時の新しい順に並べる

例：「Java 初心者 週末」で検索した場合、3語すべてを含むイベント → 2語を含むイベント → 1語を含むイベント、の順に並ぶ。

#### 入力の制限

- 全体で 100文字まで
- 単語は 5つまで。6つ目以降の単語は使わない

#### 件数と読み込み

検索結果と、ログインしていないときの一覧は、件数が多くなるので、少しずつ読み込む。

- 最初に 30件を表示する。下までスクロールすると、次の 30件を足して表示する（お知らせの一覧と同じ形。5.10）
- スクロールで読み込めないときのために、「さらに読み込む」ボタンも置く
- 検索結果は 300件までとする。300件を超えたときは、「300件以上見つかりました。単語を増やして絞り込んでください」と表示する
- 見つかった件数を表示する（例：「42件見つかりました」）

ログインしているときの「自分が申し込んだイベント」は、件数が限られるので、全件を一度に表示する。

#### URL

- 検索の条件を URL に入れる（例：`/?q=Java+初心者`）
- 検索結果の URL をほかの人に送ったり、ブラウザの「戻る」で前の検索結果に戻ったりできるようにするため
- スクロールで読み込んだ量は URL に入れない（URL を開き直すと、最初の 30件から表示する）

### 5.9 コミュニティのアーカイブ

コミュニティは削除せず、**アーカイブ**（活動を終えた状態にして、しまっておくこと）にする。コミュニティとイベントは別のデータとして扱い、コミュニティをアーカイブしても、イベントは閉じない。

#### アーカイブできる人と、元に戻すこと

- アーカイブできるのは、オーナーだけ
- オーナーは、いつでも元に戻せる
- 完全に消す機能は、MVP では作らない

#### アーカイブしたコミュニティの表示

- コミュニティ一覧（S-17）には表示しない
- コミュニティ詳細（S-05）は見られる。「このコミュニティはアーカイブされています」と表示する（イベントからたどってきた人のため）
- 管理しているコミュニティ一覧（S-16）には表示する。「アーカイブ済み」と表示し、オーナーには「元に戻す」ボタンを出す

#### アーカイブしたコミュニティでできること・できないこと

| 操作 | アーカイブ中 |
|---|---|
| 開催前のイベントの申込み、キャンセル、キャンセル待ちの繰り上げ | できる（今までどおり） |
| 開催前のイベントの編集、削除、申込者一覧 | できる（今までどおり） |
| イベント一覧（S-01）と検索に、開催前のイベントを出す | 出す（今までどおり） |
| 新しいイベントを作る | **できない** |
| 参加を申請する | **できない** |
| 参加申請を承認する | **できない**。アーカイブした時点で申請中だった申請は、すべて却下にする |
| コミュニティの名前と説明を編集する | **できない**（元に戻してから編集する） |
| メンバーの退会、除名、運営スタッフの任命・解除 | できる（開催前のイベントを運営するため） |

#### オーナーのアカウント削除との関係

5.5 のとおり、オーナーをしているコミュニティがすべてアーカイブ済みで、開催前のイベントも残っていなければ、オーナーはアカウントを削除できる。

### 5.10 お知らせ

アプリの中のお知らせ（メールは送らない）。次の出来事が起きたときに送る。

| 出来事 | 送る相手 | お知らせの例 | 開いたときの移動先 |
|---|---|---|---|
| 締め切り後に、申込みがキャンセルされた | そのコミュニティのオーナーと運営スタッフ | 「○○勉強会で、締め切り後のキャンセルがありました」 | イベント詳細（S-09） |
| イベントが削除された | そのイベントに申し込んでいた人（承認待ち、キャンセル待ちを含む。却下された人は除く） | 「申し込んでいた○○勉強会は、削除されました」 | なし（イベントがもうないため） |
| 参加が承認された | 申し込んだ人 | 「○○勉強会への参加が承認されました」 | イベント詳細（S-09） |
| 参加が却下された | 申し込んだ人 | 「○○勉強会への参加は、承認されませんでした」 | イベント詳細（S-09） |

- お知らせには、出来事が起きた時点のイベントのタイトルを残す。イベントが削除されたあとでも、何のイベントだったかが分かるようにするため
- お知らせを開くと既読になる。既読になったお知らせも消さずに、一覧に残す
- お知らせの一覧は、新しい順に、最初に 30件を表示する。下までスクロールすると、次の 30件を足して表示する（古いお知らせまで、ページを切り替えずに続けて見られるようにするため）
- 画面上部に、未読の件数を表示する
- 自分の操作で起きた出来事は、自分には送らない（例：運営スタッフが自分で締め切り後にキャンセルした場合、その人には送らない）

### 5.11 コミュニティ一覧と検索

コミュニティ一覧（S-17）は、利用者のための画面なので、自分が参加しているコミュニティを中心に表示する。コミュニティを作るボタンは置かない（コミュニティの作成は、管理の画面から行う）。

#### 何も検索していないとき

- **ログインしているとき**：自分が**メンバーとして**参加しているコミュニティを、作成日時の新しい順に、**全件**表示する。オーナーや運営スタッフをしているコミュニティは、ここには出さず、「管理しているコミュニティ」（S-16）に出す。退会したコミュニティ、除名されたコミュニティ、申請中のコミュニティは表示しない
- **ログインしていないとき**：すべてのコミュニティを、作成日時の新しい順に表示する（表示のしかたは、5.8 の「件数と読み込み」と同じ）

#### 検索したとき

- ログインしているかどうかに関係なく、すべてのコミュニティから探す（新しいコミュニティを見つけられるようにするため）
- 検索の対象は、コミュニティの名前と説明
- 検索のしかた、並び順、入力の制限、件数と読み込み、URL のルールは、5.8 のイベントの検索と同じ（並び順の「作成日時」は、コミュニティの作成日時）

#### 表示しないもの

- アーカイブ済みのコミュニティは、一覧にも検索結果にも表示しない（5.9）

### 5.12 イベント参加の承認

イベントへの参加を、オーナー・運営スタッフがすべて手で認める形にしないため、イベントごとに承認の方法を選べるようにする（Issue #43）。

#### 承認の方法

| 対象 | 選べるもの | 最初の値 |
|---|---|---|
| コミュニティのメンバー（オーナー、運営スタッフを含む） | 自動・手動 | 自動 |
| メンバー以外（ログインしている人） | 自動・手動・受け付けない | 受け付けない |

- 自動：申し込むとすぐに「申込み済み」（満席なら「キャンセル待ち」）になる
- 手動：申し込むと「承認待ち」になり、オーナーか運営スタッフが承認・却下する
- 受け付けない：メンバー以外は申し込めない
- イベントの作成（S-08）と編集（S-10）で選ぶ。編集で、あとから変えられる

#### 手動のときの動き

- 承認待ちは、定員に数えない。承認したときに席を確保する。そのとき満席なら「キャンセル待ち」になる
- キャンセル待ちの順番は、承認された順（承認待ちの間は、順番を取らない）
- 承認・却下できるのは、イベントの開始日時まで
- 却下された人は、同じイベントに申し込み直せない
- 承認待ちの人は、いつでも自分で取り消せる（席を使っていないので、締め切り後でもお知らせは送らない）
- 承認されたとき・却下されたときに、申し込んだ人にお知らせを送る（5.10）

#### 方法を変えたとき

- 手動 → 自動：承認待ちの申込みを、申し込んだ順に、まとめて承認する（定員を超えた分はキャンセル待ち）
- 自動 → 手動：すでにある申込みは、そのまま
- メンバー以外を「受け付けない」に変えても、すでにあるメンバー以外の申込みは取り消さない

#### 退会・除名・アカウント削除との関係

- 承認待ちの申込みも、ほかの申込みと同じく取り消す（5.4、5.4.1、5.5）
- 却下された申込みは、記録として残す
