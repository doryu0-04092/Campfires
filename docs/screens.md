# 画面一覧

MVP で作る画面と、その URL をまとめます。機能の ID（F-01 など）は [要件定義書](requirements.md) の機能一覧に対応しています。

## 1. 画面の分け方

画面を「**利用者の画面**」と「**管理の画面**」に分けます。アプリは基本的に利用者として使い、コミュニティのオーナーや運営スタッフが管理するときだけ、管理の画面を使います。

| まとまり | 誰が使うか | URL の頭 |
|---|---|---|
| 利用者の画面（主） | すべての人 | `/`（管理以外すべて） |
| 管理の画面（従） | オーナー、運営スタッフ | `/manage` |
| 共通の画面 | すべての人 | 画面上部と画面下部のリンクから開く |

管理の画面の URL を `/manage` で始めるのは、URL を見ただけで管理の画面だと分かるようにするためです。また、あとで「`/manage` で始まる画面は、ログインしている人だけ」のようなルールをまとめてかけやすくなります。

画面の ID は、追加した順に付けています。まとまりごとに並べ替えたため、番号は連続していません。

### URL の読み方

- `:communityId` のように `:` で始まる部分には、実際の番号が入ります。たとえば `/communities/3` は「3番のコミュニティの詳細」です
- イベントの URL は、コミュニティの URL の下に置いています。「イベントは必ずどれか1つのコミュニティに属する」という関係を、URL でも表すためです
- ログアウト（F-02）は画面を持たず、画面上部のボタンで行います

## 3. 各画面に置くもの

| ID | 画面 | 表示する内容 | 操作 |
|---|---|---|---|
| S-01 | イベント一覧（トップ） | 検索欄、イベントの一覧（タイトル、コミュニティの名前、開催日時、残りの枠数）。ログインしていて検索していないときは、自分が申し込んだ開催前のイベントを全件（「申込み済み」「キャンセル待ち」つき）。検索したとき・ログインしていないときは、開催前のイベントを最初に 30件、スクロールで 30件ずつ足す（詳しくは要件定義書 5.8） | 検索する、続きを読み込む、イベント詳細へ移動 |
| S-17 | コミュニティ一覧 | 検索欄、コミュニティの名前、説明、メンバー数。ログインしていて検索していないときは、メンバーとして参加しているコミュニティを全件。検索したとき・ログインしていないときは、すべてのコミュニティを最初に 30件、スクロールで 30件ずつ足す。アーカイブ済みは表示しない（要件定義書 5.11）。コミュニティを作るボタンは置かない | 検索する、続きを読み込む、コミュニティ詳細へ移動 |
| S-02 | アカウント登録 | 入力欄（本名、ニックネーム、メールアドレス、パスワード。本名はほかの人に表示されないことを説明する）、プライバシーポリシーと利用規約へのリンク、「同意する」のチェック | 登録する（チェックしないと押せない） |
| S-03 | ログイン | 入力欄（メールアドレス、パスワード） | ログインする |
| S-04 | コミュニティ作成 | 入力欄（名前、説明） | 作成する |
| S-05 | コミュニティ詳細 | コミュニティの名前、説明、オーナー、自分の立場、イベントの一覧（残りの枠数つき）。アーカイブ済みなら「このコミュニティはアーカイブされています」と表示する | 参加を申請する（アーカイブ中は出さない）、退会する、このコミュニティの管理画面へ移動（オーナー、運営スタッフ） |
| S-06 | コミュニティ編集 | 入力欄（名前、説明）。アーカイブ中は入力できない | 保存する、コミュニティをアーカイブする・元に戻す（確認の画面で、アーカイブ中にできなくなることを表示する。要件定義書 5.9） |
| S-07 | メンバー管理 | 参加申請の一覧、メンバーの一覧と立場 | 申請を承認・却下する、運営スタッフに任命・解除する（オーナー）、除名する（オーナー。確認の画面で、申込みが自動でキャンセルされることを表示する） |
| S-08 | イベント作成 | 入力欄（タイトル、説明、開始日時、終了日時、申込み締め切り日時、場所、定員、参加の承認の方法（メンバー：自動・手動、メンバー以外：受け付けない・自動・手動））、場所の注意書き（個人の住所を入力しない） | 作成する |
| S-09 | イベント詳細 | イベントの内容、申込み締め切り日時、定員と残りの枠数（キャンセル待ち・承認待ちの人数）、参加の承認の方法、自分の申込み状況（承認待ち、申込み済み、キャンセル待ち、却下） | 申し込む（締め切り前だけ。メンバー以外は、イベントが受け付けているときだけ）、キャンセルする（締め切り後は確認の画面を出す。承認待ちの取り消しは確認だけ）、このイベントの管理画面へ移動（オーナー、運営スタッフ） |
| S-10 | イベント編集 | 入力欄と注意書き（S-08 と同じ。承認の方法もここで変えられる） | 保存する（手動から自動に変えると、承認待ちをまとめて承認する）、イベントを削除する |
| S-11 | 申込者一覧 | 申込者のニックネーム、申込日時、状態（アカウントを削除した人は「退会したユーザー」）。本名は表示しない。承認待ち（申し込んだ順）→ 申込み済み → キャンセル待ち（順番どおり）の順に並べる | 承認待ちの人を承認する・却下する（イベントの開始日時まで。却下の前に確認を出す。要件定義書 5.12） |
| S-12 | アカウント設定 | 自分の本名、ニックネーム、メールアドレス、アカウント削除の説明（何が消え、何が残るか） | ニックネームを変える、アカウントを削除する（確認の画面でパスワードを入力する） |
| S-13 | プライバシーポリシー | 個人情報の使い方、変更した日 | ― |
| S-14 | 利用規約 | 利用のルール、変更した日 | ― |
| S-15 | お知らせ一覧 | お知らせの一覧（例：「○○勉強会で、締め切り後のキャンセルがありました」「申し込んでいた○○勉強会は、削除されました」「○○勉強会への参加が承認されました」）、未読・既読。新しい順。既読のお知らせも残す。最初に 30件を表示し、下までスクロールすると次の 30件を足す | お知らせを開くと既読になり、該当するイベント詳細へ移動する（イベントが削除されたお知らせは、移動先がないので既読にするだけ）。すべて既読にする（要件定義書 5.10） |
| S-16 | 管理しているコミュニティ一覧 | 自分がオーナーか運営スタッフをしているコミュニティの一覧と、自分の立場、承認待ちの参加申請の件数。アーカイブ済みのコミュニティには「アーカイブ済み」と表示する | 各コミュニティの管理画面（編集、メンバー管理、イベント作成）へ移動、コミュニティ作成へ移動、アーカイブ済みのコミュニティを元に戻す（オーナー） |
| S-99 | ページが見つかりません | 案内の文章 | トップへ戻る |

ボタンは、その操作ができる人にだけ表示します。ただし、これは使いやすさのためで、権限の本当のチェックはバックエンドで行います。

## 4. 画面の配置

```
┌────────────────────────────────────────────┐
│ 画面上部：ロゴ（S-01 へ）、ログイン、アカウント登録、お知らせ、アカウント設定、ログアウト │
├──────────────┬─────────────────────────────┤
│ 左側のメニュー     │                              │
│              │                              │
│ ■ ユーザー   │       各画面の中身              │
│ ・イベント一覧     │                              │
│ ・コミュニティ一覧   │                              │
│              │                              │
│ ─────────── │                              │
│ ▶ オーナー・運営スタッフ用 │                              │
│  （開くと、次が出る）  │                              │
│ ■ コミュニティ管理 │                              │
│ ・管理しているコミュニティ │                              │
│ ・コミュニティ作成   │                              │
│ ■ イベント管理   │                              │
│ ・イベント作成など   │                              │
├──────────────┴─────────────────────────────┤
│ 画面下部：プライバシーポリシー、利用規約                    │
└────────────────────────────────────────────┘
```

- 左側のメニューは、上に「ユーザー」、少し下げて区切り線の下に「オーナー・運営スタッフ用」の管理メニューを置きます。利用者の大半はふつうの参加者なので、利用者のメニューと管理のメニューをはっきり分けます
- 「ユーザー」のまとまりは、いつも開いておきます
- 管理メニューは、「オーナー・運営スタッフ用」のボタンで開け閉めします。最初は閉じておきます。開くと、「コミュニティ管理」（コミュニティとメンバーの管理）と「イベント管理」（イベントと申込みの管理）の2つのまとまりが出ます
- 管理メニューの開け閉めの状態は、ブラウザに覚えておき、画面を移動しても、次に開いたときも、同じ状態にします（開いて使う人が、毎回開き直さなくて済むように）。覚えておくのは表示の好みだけで、ログインの情報は入れません
- アカウント設定（S-12）は、普段の操作でよく使うものではないので、左側のメニューではなく、画面上部の「お知らせ」と「ログアウト」の間に置きます（ログインしているときだけ）
- 「管理者」という名前にしないのは、要件定義書で「管理者」をアプリの運営者の意味で使っているためです。コミュニティのオーナーが「自分には関係ない」と思わないようにします
- メニューには、番号（`:communityId` など）がなくても開ける画面だけを置きます。番号が必要な画面へは、一覧や詳細の画面から進みます。イベント管理の画面（イベント作成、イベント編集、申込者一覧）は、どれも番号が必要なので、本番では「イベント管理」のまとまりは表示せず、イベントの詳細やコミュニティの詳細から進みます（開発中は、下の「開発中だけの表示」の項目が入ります）
- 画面の幅が狭いとき（スマートフォン）は、左側のメニューを画面上部に移し、「メニュー」ボタンで開いたり閉じたりできるようにします

### 開発中だけの表示

動作を確認しやすいように、番号が必要な画面も、1番のコミュニティ・イベントを開く項目としてメニューに並べます。項目の名前は、ほかの項目と同じく画面の名前だけにします（「（例）」は付けません）。この項目は開発用のサーバー（`npm run dev`）でだけ表示し、本番用のファイル（`npm run build`）には含めません。

## 5. 画面の移動

```
【利用者の画面】
S-01 イベント一覧（トップ）
 └─ S-09 イベント詳細

S-17 コミュニティ一覧
 └─ S-05 コミュニティ詳細
     └─ S-09 イベント詳細

【管理の画面】
S-16 管理しているコミュニティ一覧
 ├─ S-04 コミュニティ作成 ──（作成後）──→ S-16
 ├─ S-06 コミュニティ編集
 ├─ S-07 メンバー管理
 └─ S-08 イベント作成 ──（作成後）──→ S-09
                                         ├─ S-10 イベント編集
                                         └─ S-11 申込者一覧

【利用者の画面から管理の画面へ】
S-05 コミュニティ詳細 ──（オーナー、運営スタッフだけ）──→ S-06、S-07、S-08
S-09 イベント詳細 ──（オーナー、運営スタッフだけ）──→ S-10、S-11
```

ログインが必要な画面に、ログインしていない状態で来た場合は、S-03 ログインへ移動します。
