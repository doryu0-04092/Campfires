# 技術構成

使う技術と、それを選んだ理由をまとめます。

## 1. 全体の構成

```
[ブラウザ]  React + TypeScript の画面
    │  HTTP（JSON でデータをやり取りする）
    ▼
[サーバー]  Spring Boot の REST API
    │  SQL
    ▼
[データベース]  PostgreSQL
```

画面とバックエンドを分け、間を API でつなぎます。

## 2. バックエンド

| 項目 | 技術 | 選んだ理由 |
|---|---|---|
| 言語 | Java 21 | Web 系の自社開発、受託開発、保守のどれでも使われている。21 は長期サポート版 |
| フレームワーク | Spring Boot | Java の Web 開発で最も使われている |
| ビルドツール | Maven | 設定ファイル（pom.xml）の書き方が決まっていて読みやすい。PC に導入済み |
| データベース操作 | MyBatis | SQL を自分で書くので、何が実行されるかが見える。定員の同時実行制御（行ロック）を SQL で説明しやすい |
| テーブルの変更管理 | Flyway | テーブルの作成や変更を、番号付きの SQL ファイルとして履歴に残す |
| 認証 | Spring Security（セッション方式） | ログイン状態を HttpOnly の Cookie で管理する。画面側のスクリプトからログイン情報を読み取れないようにするため |
| テスト | JUnit 5 | Java のテストの標準 |

## 3. データベース

| 項目 | 技術 | 選んだ理由 |
|---|---|---|
| データベース | PostgreSQL | Web 系の自社開発で広く使われている |
| 実行環境 | Docker | PC に直接インストールせずに動かせる。誰の PC でも同じ環境を作れる |

## 4. 画面（フロントエンド）

| 項目 | 技術 | 選んだ理由 |
|---|---|---|
| 言語 | TypeScript | JavaScript に型を付けたもの。データの形の間違いを、実行前に見つけられる |
| ライブラリ | React | 画面の部品を組み合わせて作る。現在最も使われている |
| 開発ツール | Vite | React の開発環境を素早く作れる |
| 画面の切り替え | React Router | URL ごとに表示する画面を切り替える |
| 見た目 | CSS Modules | 部品ごとに CSS を分けて書く。追加のライブラリを増やさないため |
| モック | MSW（Mock Service Worker） | バックエンドがなくても、偽の API で画面を動かす。あとで本物の API に切り替えるとき、画面のコードを変えずに済む |
| テスト | Vitest | Vite と組み合わせて使うテストツール |

## 5. 開発の順番

画面を先に作り、それに合わせてバックエンドを作ります。

1. **画面を作る**：モック（偽の API）を使って、MVP の画面を一通り動かす
2. **API 仕様書を作る**：画面が必要とする API を `docs/api` にまとめる。画面とバックエンドの間の約束事になる
3. **バックエンドとデータベースを作る**：API 仕様書のとおりに作る
4. **つなぐ**：モックを外し、画面から本物の API を呼ぶ

### 守ること

- **画面は作り込みすぎない。** このアプリの主役はバックエンドなので、画面は MVP の機能が一通り動く程度にとどめる
- **権限と業務ルールは、必ずバックエンドで守る。** 画面でボタンを隠しても、API を直接呼べば操作できてしまう。画面側のチェックは使いやすさのためのものと考える

## 6. 画面側のセキュリティ

画面を作るたびに、次の点を確認します。

| 項目 | 対策 |
|---|---|
| ログイン情報の保存場所 | ログイン情報を `localStorage` に置かない。HttpOnly の Cookie を使う |
| 秘密情報 | パスワードや API キーを画面側のコードに書かない。画面側のコードは、利用者のブラウザにすべて送られるため |
| XSS（入力された文章に仕込まれたスクリプト） | ユーザーが入力した文章を、HTML としてそのまま埋め込まない（`dangerouslySetInnerHTML` を使わない） |
| 外部パッケージ | 信頼できる有名なパッケージだけを使う。追加するときは理由を記録する |
| スクリプトの読み込み | 外部のスクリプトを読み込ませない設定（CSP）を行う |
| キャッシュ | ログアウト後に、個人の情報がブラウザのキャッシュに残らないようにする |

## 7. コメントのルール

すべてのコード（Java、SQL、TypeScript、React、HTML、CSS）に、日本語でコメントを付けます。

- **ファイル単位**：このファイルが何を担当しているか
- **関数・クラス・部品の単位**：何のためにあるか
- **行・ブロック単位**：何をしているか。見慣れない書き方には一言添える
